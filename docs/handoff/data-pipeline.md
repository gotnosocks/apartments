# Data pipeline thread handoff

Ben asked on 2026-10-15 (20:27Z) for the raw-to-fit-ready pipeline to be rebuilt on StreetEasy API
records alone, so that every value a fit reads traces back to its API record and to the evidence
behind any correction, the same inputs give the same table, and a top-up rebuilds only the
listings it changed. The pipeline runs after each backfill and each Friday top-up. The measure of
success is the time from a finished scrape to a checked, fit-ready dataset with no hand-written
steps, together with peak memory.

The work goes in nine steps, each as small reviewed PRs, so a run stays possible at any time:

1. Agree the raw layer with the scraper thread. **Done**, see below.
2. Measure the current pipeline. **Done**: [pipeline-baseline.md](../data/pipeline-baseline.md),
   regenerated by `ops/pipeline/accounting.py`.
3. Write the contract for a fit-ready row, and freeze two reference tables: the current
   pipeline's four-region API tables, and the page-crawl tables behind the served and queued fits.
4. Keep each ad's whole life as one deduplicated event log, with latest ask, first ask, days on
   market and the ending as views of it, and exclusions as flags with reasons.
5. Replace versioned rule functions and quarantine copies with an append-only corrections ledger
   that refuses entries without evidence.
6. Link ads to units and buildings to lots as a separate step, with match scores and a measured
   error rate.
7. Date every outside fact and join it as of the ad's date.
8. Build any named dataset with one command from the raw layer, caching each step by a hash of
   its code, inputs and settings, with one catalog file for datasets, snapshots, ledger versions
   and feature sets.
9. Delete the page-capture rewrite once its two readers move: Data improvements'
   `granular_export` inputs and the website's current-listings publish in
   `src/streeteasy_archive/graphql_search.py`.

## Raw layer

The scraper thread runs the collector, and it agreed on 2026-10-15 to export every stored API answer
as append-only Parquet. Its module `streeteasy_archive/graphql_export.py` reads the archive
read-only, and `ops/streeteasy-collect` runs it after each region's invocation. The layout:

- `/data1/apartments/archive/crawls/api/export/manifest.ndjson`, one line per file written.
- Records: at most 250 responses per file. Each row carries `listing_id`, `fetched`,
  `response_id`, `run`, `region`, `generation`, `outcome`, `record_sha256` and `record`, where
  `record` is `json.dumps(record, sort_keys=True)` with default separators and `ensure_ascii`, so
  its SHA-256 equals the archive's own record hash.
- Requested ids come from the stored request URL, and requests include `url_length`. Only
  answered requests appear.
- Calls go to `export/calls/run-000N/rows-FIRST-LAST.parquet`, keyed by `rowid`.
- Run 5 reads no unit histories.

The scraper thread will message once runs 1 to 4 are exported, and again for run 5. Until then
the pipeline work builds against a read-only prototype export made from the stored bodies, with
the same columns, in scratch space under `/data1`.
