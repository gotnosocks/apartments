# Brief for the next session: NYC rent model, September 24, 2026

This is the starting point for a new session with a clean context. It merges three
working sessions from September 22–24 into one: the code-review/coordination session,
Model Improvement (the PyMC line) and GPU-frontier (the from-scratch JAX line). Their
own hand-offs are in [`docs/handoff/2026-09-24/`](handoff/2026-09-24/). The durable
project contract is [`docs/project-intent.md`](project-intent.md). Read it first; this
brief updates it where noted.

## 1. Goals for this phase

Ben's priorities, in order:

1. **Ship one model.** Choose a single model and make it the app's selected model.
   The app must show each listing's residual against an estimate that does not use
   that listing's own ask. That is, use leave-own-row-out, not the in-sample fit,
   which is pulled toward the ask.
2. **Improve fit time.** All compute is local (thelio), so a full production fit
   should take tens of minutes, not ~6 hours, without giving up the exact posterior
   or the accuracy on the board.
3. **Expand geography.** Bring West Village (currently being crawled) into the
   analytical dataset, the model and the app alongside Chelsea. Then other
   neighborhoods.

The product purpose is unchanged: interpretable dollar contributions of features,
per-apartment residuals for finding over- and under-priced listings, and
counterfactuals. Forecasting unseen buildings is secondary.

  - The board shows the **Pareto frontier of fit time × row ΔELPD**.

  logged in with repo scope):
  - one unit of work per PR;
  - a reviewer other than the author (in a single session, use a reviewer subagent);
  - **squash merges only** (the repo setting). Before squashing, push an annotated
    `archive/pr-<N>` tag on the branch head, so the commits cited by run records stay

  - Never rebase a branch whose commits are cited; merge master into it instead.
  - Ben does not review PRs.

## 4. Evaluation contract

- **Splits** (seed 20260922, dataset `data/model/chelsea-product-scope-analysis-20260921`):
  - rows: 5,264 held-out rows (10% of all rows, drawn from repeat-listed units; each
    unit keeps ≥ 1 training row);
  - units: 5,226 rows (all listings of ~10% of units, each building keeping ≥ 1
    training unit).

  Both lines reproduce these row sets exactly. One small contract difference: PyMC
  unit-split screens set per-unit drift to 0 for unseen units (intervals slightly narrow),
  while the frontier line integrates it.
- **References:** per-row `heldout.npz` (`audit_id`, `lpd`, and in PyMC screens also
  `error` and `pit`) in
  `data/model/feature-screen-20260923/nuts-hwalk{,-units}/`. ΔELPD is the paired sum
  with SE √n·sd. Differing or duplicate row sets are refused.
- **Gate:**
  - split R-hat < 1.01 and bulk ESS > 400;
  - also R-hat < 1.05 over **every** element of every group effect, because
    single-building bimodality hides in samples;
  - no divergences (NUTS only; the Gibbs runs have no such concept);
  - interpretable additive dollar contributions.

  For older frontier runs, the all-effects R-hat is recomputed from kept draws at a 1.1
  threshold; new runs use exact per-chain moments at 1.05.

  Short PyMC screens that fail the gate are **screen-grade**: shown, never best.
- **Generator:** `cd frontier && uv sync --extra dev && uv run python -m rentfrontier.leaderboard`.
  It uses the frontier package's own environment, not the root `.venv`. It reads
  frontier runs from `/data1/apartments/frontier/runs/` and PyMC NUTS screens from
  `data/model/feature-screen-*/`.
- **Also report:** 95%/80% coverage (PIT), fit wall time with chains × draws and
  hardware, and dollar contributions.

## 5. First tasks, in order

1. **Measure m8 locally.** Run one m8 + desc fit on thelio under a memory cap. This
   gives the real local fit time, which is the baseline for goal 2 and a check that the
   Modal result reproduces. Commit first; `run.py` refuses a dirty tree.

   ```sh
   cd frontier && systemd-run --user --scope -p MemoryMax=2500M \
     --setenv=TMPDIR=/data1/apartments/tmp/<you> --setenv=XLA_PYTHON_CLIENT_PREALLOCATE=false \
     uv run --extra gpu python -m rentfrontier.run --split rows --model m8-drift \
     --features desc-v1 --chains 4 --warmup 900 --draws 2000 --keep-every 100 \
     --solo-scales walk_scale,bedroom_time_scale,unit_scale,unit_drift_scale,fslope_scale_0,fslope_scale_1,fslope_scale_2 \
     --name m8-desc-rows-local-<commit>
   ```

   - **GPU limits:** the RTX 2060 runs float64 at ~1/32 rate and has 8 GB. m8's
     per-chain GPU memory is unmeasured, so run a 50-draw canary first, and add
     `--chain-batch 1` if it OOMs.
   - **Chain count:** fewer chains make the R-hat gate easier to meet but less
     informative, so record the chain count.
   - **CPU alternative:** CPU JAX (`JAX_PLATFORMS=cpu`); coordinate cores with other jobs.
   - **Unit split:** also rerun m8 + desc on the unit split, to get the exact-quadrature
     score.

## 7. Working rules and pitfalls

- **Memory:**
  - Launch long jobs with `systemd-run --user -p MemoryMax=…`; session restarts kill
    `nohup` children.
  - `/tmp` is a 7.6 GB shared tmpfs with a quota, so set `TMPDIR` under
    `/data1/apartments/tmp/`. Quota errors look like test failures.
  - Put large outputs on `/data1`; the root disk is nearly full.
- **Tests:**
  - The full suite must run **one process per file** (MemoryMax 3G, `--extra app`).
    A single process accumulates past 7 GB.
  - Design reconstruction is exact only with single-threaded BLAS.
- **Open sampler item:** `test_gibbs_matches_nuts_on_same_model[tdrift]` is marked
  `xfail(strict=False)`. The unit_drift_scale posterior sd is 0.00991 for Gibbs vs
  0.00829 for centred NUTS. The walk case of the same symptom was the centred reference
  under-mixing (fixed in `1beabab`), and tdrift probably is too. Confirm with a
  non-centred reference, then remove the xfail, before relying on m8's drift-scale
  uncertainty.
- **Samplers:**
  - A centred NUTS reference can under-mix near-zero scales *without* divergences.
    Compare against non-centred.
  - Heavy tails (ν ≈ 2) plus unit effects cause per-unit bimodality, which needs mode
    hops or a data fix (110 W 26th: sized lofts and unsized small units are both "1BR").
- **Leakage:**
  - Text flags must be as-of or own-ad; later ads carried backward leaked.
  - Walk centering needs a citywide walk to absorb the common mode.
- **Hashed files:** until the old protocol is retired, never edit a file hashed by a
  running or selected fit. Check byte identity against `<fit>/protocol/`.
- **NUTS geometry:** per-building slopes on uncentered columns correlate with building
  levels under NUTS; center within buildings or expect slow mixing.
- **Formatting:** run `ruff format` only on your own changed files.
- **Environments:** don't reuse another worktree's venv for tests; stale editable
  installs import the wrong source.
- **Run records:** a frontier run records its commit, dataset SHA and feature-source SHA.
  The Gibbs-vs-NUTS agreement test uses a non-centred NUTS reference (`1beabab`).
- **Tooling:**
  - `pgrep -f` matches its own shell (use the `[x]` bracket trick).
  - Broad `jj abandon` revsets hit other workspaces.
- **Crawler:**
  - It runs from the default checkout's `.venv` and `.env`; don't `uv sync` them.
  - After any reboot, it must be restarted by hand. Check for HTTP 401/402/403 first.
